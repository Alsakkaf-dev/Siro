# بروتوكول التحديث والأوامر

مكان هذا الملف: `exchange\rashed\docs\REFRESH_PROTOCOL_AR.md`. كل الملفات للقراءة فقط من جهة الموقع. راشد هو الوحيد اللي يكتب ملفات التصدير.

## 1) متى تتحدث الملفات

| الحدث | الملفات اللي تتحدث |
|---|---|
| أي تحديث للحالة المالية (نسخة جديدة rev من CURRENT.md) | `finance.json` و`dashboard_summary.json` |
| تسجيل مصروف أو تحويل أو دخل (صف جديد في السجل) | `finance.json` و`dashboard_summary.json` |
| تحديث الصلاة أو القضاء (سجل الصلاة، أو ملف القضاء) | `prayers.json` و`dashboard_summary.json` |
| تسجيل عادة أو بداية نظام أو انتكاسة | `habits.json` و`dashboard_summary.json` |
| تسجيل وزن جديد (الجمعة) أو تغيير في الأهداف | `body.json` |
| تغيير في بنود المهام المفتوحة (OPEN_LOOPS) | `dashboard_summary.json`، وأحياناً `finance.json` (البنود المفتوحة) |
| تغيير في الروتين أو التقويم بقرار محمد | `routine.json` |

القواعد:
1. راشد يعيد كتابة الملف كاملاً (ما يعدل جزء منه).
2. بعد كتابة ملفات البيانات، يكتب `exports_meta.json` أخيراً: يزيد `version` بواحد، ويحدّث `exported_at` (وقت الكتابة) وحجم الملفات. أما `generated_at` لكل ملف فيبقى وقت **آخر تحديث للبيانات** (مثلاً آخر رصيد أو آخر تسجيل صلاة)، ولا يتغير بإعادة التصدير لو البيانات نفسها.
3. أي ملف ما تغير يبقى كما هو.
4. هذا الجدول هو الاقتراح المعتمد من راشد، وما في مجدول يشغله تلقائياً: التحديث يصير عند تفاعل راشد مع محمد (افتراض).

## 2) كيف يعرف الموقع أن الملف قديم

1. الموقع يقرأ `exports_meta.json` أولاً. فيه `generated_at` و`exported_at` العامين، ولكل ملف `generated_at` (آخر تحديث للبيانات) و`exported_at` (وقت الكتابة) و`stale_after_hours` و`bytes`.
2. يحسب عمر البيانات = الوقت الحالي − `generated_at` للملف (مو `exported_at`). ويقارن مع عمر ملف النظام (آخر تعديل) كفحص ثاني.
3. إذا حجم الملف الفعلي يختلف عن `bytes` فالملف تغيّر بعد التصدير: يعرض «غير متسق».
4. الحالات (الحدود **افتراض**، يعدلها محمد):

| الملف | قديم بعد | منتهي بعد (3 أضعاف) |
|---|---|---|
| `finance.json` و`dashboard_summary.json` | 24 ساعة | 72 ساعة |
| `prayers.json` | 12 ساعة | 36 ساعة |
| `habits.json` | 24 ساعة | 72 ساعة |
| `body.json` و`routine.json` | 7 أيام | 21 يوم |

5. العرض: «محدّث» ثم «قديم: آخر تحديث قبل كذا ساعة» ثم «منتهي». إذا `exports_meta.json` مفقود أو ما ينقرأ، يعرض «غير متاح».
6. القِدم حسب الوقت فقط. ممكن يصير تحديث في راشد بدون تصدير، فالموقع يعرض دائماً `generated_at` بجانب الرقم، ويقدر يرسل أمر `refresh_exports` (انظر تحت).

## 3) كيف يرسل الموقع أمراً لراشد

المسار: `exchange\rashed\commands\`. الموقع يكتب ملف JSON جديد، وراشد يقرأه.

**القاعدة الأساسية:** راشد **لا ينفذ أي أمر** إلا بعد موافقة محمد **الصريحة في المحادثة**. وجود الملف في المجلد ليس إذناً. راشد يعرض على محمد نص الأمر (النوع والبيانات)، وينتظر «موافق». بدون موافقة يبقى الأمر `pending` أو يصير `rejected`.

الخطوات:
1. الموقع يكتب `commands\<id>.json` بحالة `pending`. الاسم يطابق `id`. لا يعدل ملفاً موجوداً ولا يحذف.
2. راشد يقرأ المجلد عند تفاعله مع محمد (ما في مراقبة تلقائية) ويتحقق: الصيغة صحيحة، النوع مسموح، الـ `id` ما نُفذ قبل، و`created_at` ليس أقدم من 24 ساعة (افتراض).
3. راشد يعرض الأمر على محمد في المحادثة.
4. موافقة محمد: الحالة `approved` ثم ينفذ ثم `executed` (أو `failed` مع السبب). رفض أو سكوت: `rejected` أو تبقى `pending`.
5. راشد يحدّث حقل `status` وحقلي `handled_at` و`result_note_ar` في نفس الملف، ثم يحدّث ملفات التصدير المتأثرة (القسم 1).
6. تنفيذ الأمر مرة واحدة فقط لكل `id`.
7. الأوامر ما تغيّر التقويم ولا ترسل رسائل ولا تحذف شيئاً.

## 4) صيغة الأمر (schema)

```json
{
  "id": "CMD-20261026-180500-001",
  "created_at": "2026-10-26T18:05:00+08:00",
  "type": "log_expense",
  "payload": { },
  "status": "pending"
}
```

| الحقل | النوع | المعنى |
|---|---|---|
| `id` | نص | رقم فريد: `CMD-` ثم التاريخ والوقت ثم رقم تسلسلي |
| `created_at` | نص ISO مع `+08:00` | وقت إنشاء الأمر |
| `type` | نص | واحد من: `log_expense`، `log_prayer`، `start_habit`، `habit_relapse`، `refresh_exports` |
| `payload` | كائن | بيانات الأمر حسب النوع |
| `status` | نص | `pending` عند الإنشاء. ثم `approved`، `rejected`، `executed`، `failed`. و`example` للأمثلة فقط |
| `created_by` | نص (اختياري) | `"site"` |
| `handled_at` | نص (يكتبه راشد) | وقت المعالجة |
| `result_note_ar` | نص (يكتبه راشد) | نتيجة بسيطة بالعربي |

حقول `payload` حسب النوع:

| النوع | الحقول |
|---|---|
| `log_expense` | `date`، `amount`، `currency` (RM)، `box` (treasury أو monthly أو daily أو unknown)، `category_ar`، `label_ar`، `payment_source` (rhb أو tng أو cash أو unknown) |
| `log_prayer` | `date`، `prayer` (fajr أو dhuhr أو asr أو maghrib أو isha)، `status` (in_time أو late أو missed)، `kind` (fard أو qada) |
| `start_habit` | `habit` (vape أو tea_sugar أو water أو sleep أو food أو workout)، `start_date`، `note_ar` |
| `habit_relapse` | `habit`، `date`، `note_ar` |
| `refresh_exports` | `files` (قائمة أسماء، أو فاضية للكل) |

الأمثلة في `commands\examples\` (للتوضيح فقط).
